T3O-49 UX spec · board, card and settings

CI and project-based stages, v2

One global list of stages with per-project switches and overrides, edited on the board rather than in t3o.json. CI becomes a list of typed steps per project with parallel groups and a built-in Sync with base. Each screen below is shown in light and dark, with numbered notes and the interaction flows. Interactive versions: the board (Tweaks → CI demo states for the rarer CI states) and Settings. Updated for T3O-57: CI now fixes in place and stops for a human instead of sending cards back to Code review, and projects get a Stop on failure setting. Jump to the T3O-57 screens.

Status colours (docs/t3o/status-colours.md) and motion
Green · done only Blue · running, including a fix agent at work Violet · waiting on a human Amber · blocked or failed check (never red) Grey · cancelled Pink markers · spec annotations, not UI
Nothing on a card face animates. Inside the open card, the only motion is the existing shimmer on a running step's name, which pauses when the tab is hidden and under reduced motion. This pass also removed the pulsing "thread running" dot and the pulsing planning pip from card faces, and moved CI failures from red to amber everywhere.
T3O-57

CI fixes in place · Stop on failure

Two changes to the CI stage. A new per-project setting, Stop on failure (default Yes), decides whether a failed step stops the steps after it. And CI never sends a card back to Code review by itself any more: when a pass fails, a fix agent fixes every reported failure and CI re-runs from the top, up to the fix-attempt limit (default 3). If attempts run out, or the agent says it can't fix something, the card stops in CI for a human (violet "Needs you"). Sections 3b, 5 and 6 below are updated to match.

A pass fails (either setting)
  1. Stop on failure Yes: the failed step's group finishes, later steps are cancelled. No: every step runs to the end.
  2. The fix agent gets every reported failure at once, fixes, commits and pushes. Chip "Fixing", line "N of 6 steps failed · fix 1 of 3".
  3. CI re-runs from Sync with base. A clean pass moves the card to Ready for merge, where auto-merge holds if any fix was committed.
The card stops for you
  1. Fix attempts run out with steps still failing, or the agent reports with board_report_ci that it can't fix a step.
  2. The card stays in CI with a violet "Needs you" and the reason. Nothing moves it on its own.
  3. Retry CI (fresh visit, attempts reset), Send back to review anyway (recorded under your name, failures attached as a finding), or Skip CI.

Interaction flows

Switch a stage off for one project
  1. Board: click a column's half-circle → popover → the project row (or Settings → Projects → project → Pipeline).
  2. Flip the stage's switch. No confirm; it saves at once ("Saved just now").
  3. Cards already in that stage stay; in that project's view the column shows as retired until they move on. New cards skip it.
Override a setting, then undo it
  1. Project → Pipeline → expand the stage → change the value. The row turns overridden with the global value beside it.
  2. Reset to global clears the override, as does setting it back to the global value (except prompts).
  3. "Reset everything to global…" in the page header confirms, then clears every switch, override and CI step.
Build a CI pipeline
  1. Project → CI → Add step (or the one-click starter). The new step opens expanded; CI switches on with the first step.
  2. Toggle "Parallel with previous" to join a group; the group box appears immediately, with the worktree warning if two scripts share it.
  3. Drag to reorder; the drop line shows where it lands. Removing a step needs no confirm (undo via toast).
Import a t3o.json
  1. Notice (Settings → Board, project page, or the board pill) or Project → Import & export → Import…
  2. Confirm shows summary chips and per-change lines, and states it replaces this project's differences.
  3. Replace and import applies, clears the notice and toasts the summary. No thanks hides it until the file's SHA changes.
Watch and dig into a run
  1. Card face shows segments and one status line; click opens the card on the CI tab while it's in CI.
  2. Expand a step; View live log opens the follower; Open on GitHub opens a popup window.
  3. Fix agent box links to its thread. Skip CI asks to confirm and records the skip by name.
Back from Ready for merge
  1. Ready for merge finds a stale base, conflicts or failing forge checks on a CI project and sends the card back to CI.
  2. A new pass starts at Sync with base; the face shows "Back from Ready for merge: base moved", the tab a banner, and the activity feed a row.

Suggested cuts for v1, and forge tiers

CutBoard import pill. Settings notices plus the sidebar dot are enough to discover a t3o.json; the pill can follow.
CutStyled hover tooltip on partial columns. Ship the native title for the summary; keep the click popover.
CutLive log streaming. v1 can show the log after the step finishes plus the progress fraction while running; live follow, pause and jump come next. The viewer's shape stays the same.
CutDrag reorder. Up/down buttons on each row cover it; drag is a nicety.
CutPer-project fix-agent prompt override. Attempts and model are enough per project; the prompt stays global.
Cut"+N more" collapse for 4+ import notices. Rare; show them all.
KeepMust stay in v1: amber failures, static card faces, Sync with base, parallel groups with the worktree warning, the import confirm summary, and the forge "can't be read" blocked state, since without it those cards would sit in CI forever.
