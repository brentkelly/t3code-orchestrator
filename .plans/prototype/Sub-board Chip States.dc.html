Sub-board chips: filled means being worked

Today every child in the build process paints the same solid blue, so a parent card reads “4 building” when one of them is queued. The chip colours stay as they are (blue building, purple awaiting input, green done). What changes is the fill: a solid chip is actively being worked, and a hatched chip is in that state but waiting for a slot. Building and code review are both blue, so a card queued for review is hatched blue too.
