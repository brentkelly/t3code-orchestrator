Planning UX

Proposed split and plan review, working together

Big features usually get both a proposed split and an adversarial plan review, and right now they fight for the card. The split panel covers the thread while the review runs. Approving the split hides the planning UI even though planning hasn't finished. Turning on review alone takes three clicks. And each click on the rounds stepper sends the agent another prompt. These changes treat the split as one planning output that waits for review to finish. It doesn't replace the planning screen.

4bFour automation gates: plan, sign-off, build, merge

Every card passes four gates, and each toggle automates exactly one. Plan: the agent plans without asking you. Sign-off: the plan is approved without you. Build: an approved card starts once its dependencies are done. Merge: finished work merges once code review passes. Sign-off only exists when planning is automated, by auto-plan or an unattended review.

a

The rounds count is card state. The planning agent reads the current target at each round boundary (the same way it reads its brief), so the stepper never sends a prompt. Lowering it below the current round ends the review after that round.

b

If a message is unavoidable (the agent is idle and has to be woken up), send at most one, 1.5s after the last click, carrying the final value. A newer one replaces an earlier queued one rather than stacking behind it.

c

Toggling on when a plan already exists arms the review with the default rounds and shows Start review, so you can set rounds first. When there's no plan yet it starts by itself once the plan is posted, as it does today.
